# Step Back 0.1.0 — 创建交付

任务：阶段结束后不把关联新问题当作未完成责任。版本为初始公开候选，发布状态以 GitHub 实际 Release 为准。

研究：step-back 提供检查点与信息价值原则；smallest-complete 提供范围内完整交付和停止原则；gpt56-stop-overengineering 用于工程型方案对照。来源与取舍见 prior-art-research.md。

设计优势：新增“完成后询问”和“明确执行”的区别，已批准多阶段任务不增加审批。舍弃工具计数、状态机、后台监控及广泛架构要求。

验证边界：包格式、单一入口、身份、内部链接、许可证保留可离线检查；trigger-eval.json 是词面启发式冒烟检查，不是模型触发测试。有限子代理场景演练不等于盲评或长期成效。跨 Agent 自动发现、重复运行稳定性、与上游的公平对比均为 missing evidence。

维护与回退：源码版本化，发现实际边界错误后再修订。通过原安装治理渠道撤销激活和入口段即可停止使用；不删除其他技能、不重置用户配置。发布包无运行时脚本或外部权限；tests 仅维护时使用。

公开边界：不包含私人对话、个人安排、项目路径、账号凭证或本机治理文件。MIT 已获用户授权；维护者 Jhyphlau。发布与本机激活由包外的治理工具执行，不授权本 Skill 自行发布或安装。
